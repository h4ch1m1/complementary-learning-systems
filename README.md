# Papers

Interactive paper explanations and executable PyTorch tutorials. The public GitHub repository keeps its existing name so published website and Colab links remain valid.

## Website structure

This is a static GitHub Pages site; no build step is required.

- `index.html` redirects to `website/semantic_knowledge.html`, preserving chapter hashes.
- `website/semantic_knowledge.html` contains the CLS introduction and four model chapters. Its inline router switches chapters using `#introduction`, `#semantic`, `#rat`, `#monkey`, and `#equations`.
- `website/book_navigation.js` synchronizes the chapter outline, notebook downloads, and Colab links; it is specific to the CLS page.
- `website/book_theme.css` supplies the shared reading layout and paper selector styles.
- `website/paper_navigation.js` contains the paper catalog and creates the top-left selector from each page’s `body[data-paper]` identifier.
- `website/semantic_memory.html` presents Rogers et al. (2004), with model explanations, measured lesion results, and reproduction notes. `semantic_memory.js` handles chapters and the measured-results slider; `rogers_results.js` is generated by `notebooks/rogers2004/export_website.py`.
- `notebooks/` holds executable notebooks, `outputs/` holds embedded interactive figures and simulation results, and `assets/` holds supporting images.

To add a paper, create its HTML page beside the existing pages, include `book_theme.css` and deferred `paper_navigation.js`, provide a `body > aside .book-title` fallback, and set a unique `data-paper` on the body. Add the same ID, filename, title, and citation to the `papers` array in `paper_navigation.js`. Each paper owns its chapter links and content. Remove the `status` entry when its content is ready. Keep the existing CLS filename and chapter hashes so published links continue to work.

## Rogers et al. (2004) reconstruction

`notebooks/rogers2004/` contains a self-contained PyTorch notebook, model, numerical tests, and plotting script. `outputs/rogers2004/` contains measured training and lesion results. This is a mechanism reconstruction using newly generated feature vectors, not a claim to recover the original numerical curves. Read `notes/ROGERS2004_NOTES.md` for settings, departures, source provenance, and commands. The website's Rogers page distinguishes the original reconstruction from the optimized extension and links both notebooks.

The follow-up tuning comparison is in `outputs/rogers2004/tuning/REPORT.md`.
It preserves the original run, reports failed settings, and distinguishes
paper-like continuation from extended-time and Adam optimization experiments.
`selection.json` records selection on intact performance before fresh lesion tests.

Rogers teaching interactives compare saved feature vectors, play actual retrieval trajectories, and inspect independent lesion examples. Regenerate their offline data with notebooks/rogers2004/export_explorers.py. The three example masks per level use seeds separate from the aggregate lesion experiment.

## Paper organization

- `notebooks/cls1995/`: McClelland, McNaughton & O’Reilly (1995), grouped into semantic, rat, monkey and two-system models.
- `notebooks/rogers2004/`: Rogers et al. (2004), including the full `tutorial.ipynb`, model implementation, original reconstruction and optimization records.
- Old notebook paths contain migration links to the corresponding CLS notebook.
- Shared website layout and controls live in `website/`; `paper_navigation.js` is the paper catalog. New papers receive their own ID, notebook directory, and page.
- Supporting files remain in `assets/`, `data/`, `outputs/`, and `notes/`. Rogers files use the `rogers2004` namespace; the pre-existing CLS assets retain their URLs.

## Rogers Colab tutorial

[![Open in Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/h4ch1m1/complementary-learning-systems/blob/main/notebooks/rogers2004/tutorial.ipynb)

`notebooks/rogers2004/tutorial.ipynb` follows the article from motivation through representation, recurrent updates, learning, and lesion experiments. The default run loads the supplied checkpoint, runs a short optimization example on a copy, and provides live Python widgets. Full retraining and 50-mask lesion evaluation are optional. A clean Colab runtime downloads the repository and installs missing dependencies; no local drive path is required.

The notebook is generated by `python notebooks/rogers2004/build_tutorial.py`. Its final published version is executed to include figures. The original paper settings and optimized extension are distinct; numerical details remain in the reproduction notes.

`website/sketch_controls.js` and `sketch_controls.css` provide pencil outlines and light diagonal shading for compact bordered controls. Large containers, sidebar separators and data grids are not restyled.
